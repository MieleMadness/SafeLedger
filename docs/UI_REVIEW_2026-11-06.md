## Findings and changes

| Before | After | Why |
| --- | --- | --- |
| P1: Search declared itself modal but Tab could reach the obscured workspace; closing discarded focus. | Tab and Shift+Tab wrap within its controls; closing restores the connected invoking control. | Keeps the keyboard path visible and predictable. |
| P2: An old search reply could render during the next query's 100 ms debounce; Enter could activate an old result. | Input immediately invalidates outstanding replies and clears obsolete results. | Prevents navigation from outdated search results. |
| P2: A pending debounce could survive close/reopen. | Closing cancels its timer and invalidates outstanding requests. | Prevents unnecessary requests and updates from a previous dialog. |
| P2: Search had only an ESC hint, and its field had no explicit accessible name. | Added a labeled Close button and explicit field name; retained Escape and Ctrl/Cmd+K. | Makes dismissal discoverable and the field identifiable. |
| P2: Result updates were not announced and result focus used only a subtle background change. | Added a polite live region and a theme-token focus outline. | Improves feedback for keyboard and assistive-technology users. |
| P2: The three workspace filter fields relied on placeholders. | Added explicit accessible names without changing their visible copy. | Names remain available after users enter text. |

Production changes are confined to `global-search-ui.js`, `css/global-search.css`,
and the three filter labels in `index.html`. The search privacy allowlist,
encryption, authentication, storage formats, and release version are unchanged.

## Scope and remaining observations

This was a source review focused on interface accessibility, search lifecycle,
and existing architecture/security regression coverage. It is not an exhaustive
security audit or proof that the entire codebase is defect-free. No overall
accessibility score is assigned from a partial UI review.

The CSS ownership audit reports 257 repeated selector/context pairs and 529
important declarations, but zero identical duplicates or provably shadowed
important declarations. These are maintenance signals, not verified removable
rules; broad deletion would risk the established three-theme cascade.

Manual screen-reader speech, native keyboard input across the entire app,
physical touch, and packaged Linux/macOS execution were not tested in this pass.
The new smoke fixture dispatches keyboard events in real Chromium to exercise
the handlers; it does not claim OS-level assistive-technology verification.
Hands-on encrypted backup/restore and interruption recovery remain release
validation tasks. Generated offline icons and installed dependencies are local
build outputs, not part of the proposed source patch.
